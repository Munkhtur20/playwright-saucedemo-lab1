## Юу хийсэн
- https://www.saucedemo.com дээр Playwright (TypeScript)-ээр 3 тест бичсэн (tests/mytest.spec.ts): амжилттай нэвтрэх, буруу нууц үгээр нэвтрэх (сөрөг тест), нэвтэрсний дараа бараа сагслах.
- Нэвтэрсэн тест бүр logout хийж, нэвтрэх хуудас руу буцсан URL-ээ шалгаж дуусдаг. Тест бүр өөрөө нэвтэрдэг тул хоорондоо хамааралгүй.
- docs/codegen.ts: codegen-ээр бичүүлсэн код.
- docs/login-pass-trace.zip: амжилттай ажилласан trace.
- docs/failed-trace.zip: toHaveText('Produkts') гэж санаатай унагасан тестийн trace.
- docs/playwright-report/: HTML report.

## Locator сонголт, XPath-аас зайлсхийсэн шалтгаан
Нэвтрэх товчийг getByRole, талбаруудыг getByPlaceholder, бусдыг нь getByTestId (data-test атрибут)-аар олсон. XPath нь хуудасны бүтцээс хамаардаг тул дизайн өөрчлөгдөхөд тест тасарна, уншихад ч хэцүү. Харин role, placeholder, test id нь хэрэглэгчид харагдах утга эсвэл тогтвортой атрибутад тулгуурладаг. Анх Logout-ийг getByRole('link', { name: 'Logout' })-ээр хайхад 30 секунд хүлээгээд унасан. getByTestId('logout-sidebar-link') руу шилжүүлсний дараа тест ногоон болсон. Үүнээс role-оор олох нь үргэлж ажилладаггүй, тэр үед data-test атрибут найдвартай сонголт гэдгийг ойлгосон.

## Codegen ба миний кодын ялгаа
Codegen зөвхөн дарсан, бичсэн үйлдлийг бичдэг бөгөөд assertion (expect) огт байгаагүй. Тиймээс юуг шалгаж байгаа нь тодорхойгүй, зөвхөн бичлэг болж үлддэг. Мөн login-container дээр хоёр удаа click, username дээр dblclick гэх мэт давхардсан үйлдэл гарсан. Codegen ихэнх элементийг locator('[data-test="..."]') гэсэн CSS selector-оор олсон бол би getByRole, getByPlaceholder, getByTestId ашигласан. Миний код logout хийсний дараа URL-ээ шалгадаг, codegen шалгадаггүй. Гэхдээ codegen-ээс Logout-ийн data-test нэрийг олж харсан нь миний алдааг засахад тусалсан.

## Trace viewer дээр харсан зүйл
Assertion-ыг 'Produkts' болгоход тест унаж, trace дээр Expected: "Produkts", Received: "Products" гэж харагдсан. Алдаа аль алхам дээр гарсан, тэр үеийн хуудасны байдал ямар байсныг алхам алхмаар нь харж чадсан. Дараа нь буцааж засаад бүх тест ногоон болсон.

## Playwright ба Selenium-ийн ялгаа
Playwright дээр элемент бэлэн болтол автоматаар хүлээдэг тул sleep, explicit wait бичээгүй. Selenium дээр WebDriverWait гараар бичих шаардлагатай байдаг. Суулгалт нэг командаар (npx playwright install) хөтчүүдийг татсан бөгөөд тусдаа driver тохируулах шаардлагагүй байсан. Codegen нь үйлдлээ код болгож өгдөг тул тест бичих эхлэлд тустай, гэхдээ assertion-ыг өөрөө нэмэх хэрэгтэй. Trace viewer нь тест унасан шалтгааныг алхам бүрээр нь харуулдаг тул лог, скриншотоос илүү хурдан байсан. Тестүүд хоорондоо хамааралгүй зэрэгцээ ажилладаг тул 3 тест хэдхэн секундэд дууссан. Харин Selenium нь олон хэлтэй, олон жил хэрэглэгдсэн учраас хуучин төслүүд, баримт бичиг ихтэй. Миний хувьд энэ лаборатор дээр Playwright илүү хурдан, тогтвортой, алдаа олоход хялбар санагдсан.
